# GetFrame animation scheduling and frame bank integration

2026-10-10, Engine.dll `1055f217..1055f28f`, followed by the proven decode/output
loops. Module `crates/rc-package/src/vertmesh_animation.rs`, CLI
`rc-vertmesh-animation-check`. Five completed tasks:

1. Read supplied sequence start/count and channel time, clamp negative time to zero.
2. Reproduce float32 frame product, temporary MXCSR floor conversion and fraction.
3. Compute current/next cyclic frame offsets, including the last-to-first transition.
4. Read flattened packed position/normal banks and drive GetFrame decode/output.
5. Feed animated bytes into transactional geometry, upload and material draw replay.

## Native arithmetic

`Clock.sequence` is the supplied return of `ULodMeshInstance::GetSequence(0)`;
this batch does not implement that function. Sequence fields are signed start at
`+0c` and signed count at `+10`; channel float32 time is at `+1c`.

A null sequence selects packed frame zero and does not read channel time. Otherwise
the native code uses ordered comparison to clamp negative time to positive zero;
negative zero survives. It converts count to float32, multiplies by time, loads
MXCSR `3f80`, converts the stored product to signed integer, then loads `1f80`.
The temporary rounding mode is toward negative infinity. The fraction is the
float32 product minus the integer converted back to float32, with no FMA.

Current vertex offset is `(integer % count + start) * vertex_count`; next uses
`integer + 1` before the remainder. A strictly positive fraction chooses the
interpolation path. Whole cycles wrap; one-frame sequences may interpolate the
same frame with itself. No rate scaling, time progression or loop flag was
invented: the supplied channel time is used exactly as this GetFrame body uses it.
The Rust implementation produces the same arithmetic without changing the host
thread's floating point control register.

## Bank access and transaction

`Input.positions` / `normals` represent flattened mesh `+60` / `+130` word arrays.
`resolve` slices only `min(requested_count, vertex_count)` active words from the
computed offsets. A zero count does not read either bank. A zero fraction does
not read the next frame, even though native scheduling computes its offset.
The resulting frame input uses the previous packed decode/interpolation/output
implementation, preserving UV bytes, stride padding, cache tails and wedge skips.

`Runtime.submit_animated_frame` calls the existing transactional frame/geometry
adapter. On success it commits the cache, generated bytes and nested geometry;
on failure the original request and runtime remain unchanged, including failures
after index generation, unlock or material lookup. Geometry LOD remains the value
before GetFrame's vertex-count clamp. This adapter starts with an already selected
sequence and geometry LOD; it does not yet execute the full camera/actor call tree.

Safe-port bounds: vertex/request counts 0..65536, positive signed sequence count,
nonnegative start, finite time/product with product below 2^31. Checked frame-index,
vertex-offset and byte-offset arithmetic rejects native wrapping address cases.
Each bank is bounded to 4,194,304 words; actual active ranges must be present.
Existing cache/layout/destination limits still apply. These checks intentionally
reject unsafe native inputs rather than emulate invalid memory or integer traps.

## Validation

The original assembly is executed by the restricted x86 replay VM, including both
`LDMXCSR` instructions, `CVTSS2SI`, signed remainder, offset multiplication and the
original decode/output bodies. Packed banks remain at their full synthetic base
addresses: the replay does not relocate selected frames to an artificial frame zero.
VM support accepts only MXCSR `1f80`/`3f80`; it is not a general floating point
environment emulator. All SSE arithmetic outside the temporary integer conversion
continues to use the existing float32 implementation.

**50 draw sequences / 146 requests**, **686,076 original instructions**, 2,628
indices, 146 vertex and 146 index uploads, **438 draws / 876 material passes**.
